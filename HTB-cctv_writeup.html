اكتشاف ZoneMinder

عند زيارة http://cctv.htb/zm/ نجد ZoneMinder — وهو نظام مراقبة CCTV مفتوح المصدر.

ZoneMinder هو نظام مراقبة بالكاميرا مفتوح المصدر يُستخدم في الشركات والمنازل. يحتوي على واجهة ويب وAPI.

💡 لماذا نجح admin:admin؟

ZoneMinder يأتي بكلمة مرور افتراضية admin:admin. كثير من المديرين لا يغيرونها — وهذا خطأ أمني شائع. هذا النوع من الضعف يُسمى Default Credentials.

عند محاولة استخدام -b cookies.txt مع الـ API، يرجع 401 Not Authenticated — لأن ZoneMinder يعتمد على JWT tokens وليس session cookies.

كسر مصادقة motionEye API — HMAC Signature

قراءة كود المصادقة

قرأنا كود Python الخاص بـ motionEye لنفهم كيف يعمل نظام المصادقة:

Python — /handlers/base.py # مقتطف من كود get_current_user():

admin_password = main_config.get('@admin_password')

# يحسب HMAC-SHA1 من password أو hash(password)
if username == admin_username and (
signature == utils.compute_signature(method, uri, body, admin_password)
or signature == utils.compute_signature(method, uri, body, admin_hash)
):
return 'admin'

# الجزء المهم — إذا ما في _username ولا normal_password:
if not username and not normal_password:
return 'normal' ← يُعامَل كـ normal user بدون auth!
💡 كيف يعمل HMAC في motionEye؟

التوقيع (signature) يُحسب هكذا:

  • Key: admin_password (أو SHA1 منه)
  • Message: METHOD + ":" + URI + ":" + SHA1(body)
  • Algorithm: HMAC-SHA1

المشكلة: admin_password مخزون كـ SHA1 hash في الملف، ونستطيع قراءة الملف!

الدروس المستفادة — Lessons Learned
المشكلة النوع الحل الصحيح
admin:admin في ZoneMinder Default Credentials تغيير الكلمة الافتراضية فوراً عند التثبيت
admin_password hash مقروء لمستخدمين آخرين Insecure File Permissions تقييد قراءة /etc/motioneye/ لـ root فقط
motionEye يسمح بتعديل الأوامر المُنفَّذة Command Injection via API تقييد الوصول لـ API + التحقق من المدخلات
motion daemon يعمل كـ root Unnecessary Privilege تشغيل الخدمة بمستخدم محدود (motion user)
mark:opensesame — كلمة مرور ضعيفة Weak Credentials استخدام كلمات مرور قوية + 2FA

مبادئ أمنية انتُهكت في هذا الـ Machine

  • Principle of Least Privilege: motion daemon لا يحتاج صلاحيات root
  • Defense in Depth: فشل طبقة واحدة أدى لاختراق كامل
  • Secure by Default: الإعدادات الافتراضية كانت غير آمنة
  • OWASP A05: Security Misconfiguration: إعدادات خاطئة في كل مكان
  • OWASP A02: Cryptographic Failures: SHA1 hash مكشوف بدلاً من تشفير صحيح
